## Gates and evidence boundaries

At #135, quality CI `39010093175` passed 320 suites / 3,803 tests (+1 inherited platform skip), with 83 Browser cases and no retries; Azure `39010093218` passed. Resulting main tree `fe838847167f6f984b914cc3c7afa477e9fcd509` matches the tested tree.

Packaged Electron tests use `PACKAGED_APP_PATH` and fail when an executable is required but missing. The existing release workflow owns platform packaging/runtime jobs; it has not been triggered by this improvement task. Local package evidence is from genuine dependencies and an unsigned macOS arm64 artifact built with `--publish never`; it is not Windows CI or a published release. See the [execution ledger](2026-10-17-project-improvement-execution.md) for batch-specific source/package evidence.

Dependency remediation removed known high/critical findings in the reviewed baseline, but ten moderate findings remain. The isolated global-agent 4.1.3 candidate was rejected after a real HTTPS proxy regression despite its zero-advisory result. Its override is excluded. Wiring the documented dependency audit into the release gate is a separate prepared batch; no release was run to test it.

Real HTTP fixtures do not establish live-service acceptance. Worker protocol mocks do not establish a real Worker. A source Electron launch does not establish a packaged artifact. A package launch does not establish a physical projector or Windows installation. Cold-cache offline behavior is not inferred from warm-cache reload.
