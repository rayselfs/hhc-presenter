# Turbo Chinese and mixed-speech validation

日期：2026-11-02。結論：**保留具長句保護的 Turbo 作為中文加強方案候選；不直接替換 Small，也不宣稱混說已達可接受品質。** 全部修改限 benchmark，產品 runtime 與定位政策未變。

## Method

- M4／24 GiB、Metal、4 threads；固定 Whisper large-v3-turbo Q5_0、greedy、中文 hint、無 prompt。模型 revision／hash 沿用 Phase 0 manifest。
- 與先前 Small 使用同一批 WAV、target 與 v2 `phonetic-0.85` 政策；比較程式驗證逐筆 ID、SHA-256、target、kind、duration，不容許漏樣本或改答案。
- 第一批中文 312 筆；第二批中文 108 筆，依上一輪既定原文去重排除 `v2-097`，其餘 107 筆。`v2-129` 是英文，不在本輪中文輸入。合計 419 筆，其中 377 正例、42 負例。未重跑英文模式。
- 這是已使用過的合成回歸資料，**不是新盲測、真人標註或現場驗收**。先固定 `audio_ctx=768` 驗證，再因長句退步新增按音訊長度選擇 context 的保護，最後完整重跑兩批與邊界測試。
- Small 重用先前實測輸出／耗時；Turbo 本輪重新推論。時間包含 ASR、正規化與固定定位規則，索引已建立；不包含收音、VAD endpoint、IPC、UI。沒有用只量 parser 的時間冒充三秒。

## Fixed context exposed a real regression

固定 768 context 在 419 筆均低於三秒，錯誤候選為零；但 4 段超過 15.36 秒的朗讀（0291、0292、0297、0298）全部由 Small 正確變成拒答。額外把同一句中文／混說口令從音訊開頭移至第 16 秒，固定 768 也全部漏掉後段口令。這種加速不能直接採用。

完整 context 對照救回 4 段朗讀及 2 段後段口令，這組對照最慢 2.030 秒。測試工具新增 `--fit-audio-context`：音訊不超過 768 個 audio tokens 時用 768；超過時在第一次推論前就用完整 context，不裁切音訊、不重試第二次辨識。完整 context 是引擎既有選項，沒有增加第二個模型。上游 context 實作可參照 [whisper.cpp](https://github.com/ggml-org/whisper.cpp/blob/master/src/whisper.cpp)；本輪採用依據是以下實測，而非只看上游程式推論有效。

額外 6 筆邊界樣本獨立計算：4 筆口令（開頭／第 16 秒）全部正確，2 筆純靜音均未形成候選，最慢 1.624 秒。靜音仍可能產生無關字幕文字，因此 VAD 與候選安全規則不可刪除；不能把「沒有導航」說成 ASR 沒有幻覺。

混說退步例包含 `verse five` 變成重複的無節標記數字，或 `verse` 變成 `Vers`。本輪不新增例外放寬定位規則，也不靠預期答案回填。這些個案仍需獨立格式／負例測試及真人證據，不能為了提高此批分數直接自動接受。

## Recommendation and verification

保留本輪 Turbo 長句保護原型，中文朗讀改善值得繼續驗證；淘汰固定縮短 context 的方案。混說仍弱，不把「較大模型」當成所有情境都更準，也不在這批資料上調寬 fuzzy 門檻。待真人標註完成後，再決定是否讓 Turbo 成為「加強辨識」選項；預設引擎暫不切換。

13 項 Python benchmark tests 通過，包含成對資料完整性、超時不能算及時成功、錯誤候選計數及 context 邊界。重現步驟見 [README](../../scripts/speech-benchmark/README.md)，[evidence](evidence/turbo-chinese-validation-20261102/) 保留 raw 推論、逐筆政策輸出、配對摘要、protocol 與 hash。沒有納入私人錄音或 AI 逐字稿。

真人正確率、Windows 11 i7／32 GB、現場三秒端到端、長時間負例與正式 UI 導航仍未驗證。98% gate 未通過，沒有 merge、tag 或 release；本輪沒有產品變更，未執行全 app build／完整 CI。
