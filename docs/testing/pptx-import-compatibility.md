# Editable PPTX compatibility matrix

> Historical PR #96 design/evidence, retained from source `4eaa86b4`. Test counts and release gates below describe that earlier branch, not the integrated main. See [the integration record](/docs/reports/2026-10-30-pr96-integration.md) for current scope, validation and remaining acceptance.

## Admission and preservation policy

Ordinary upload and raw/provider “Edit a copy” use the same bounded package inspection, source-feature checks and conversion validation. Unsupported input fails before creating an editable catalog item, document blob or read-only-source draft. The original record and bytes remain intact. Supported ordinary imports/copies write schema v1; read-only sources create the existing local draft. Source-backed v2 fixtures remain explicit test paths pending separate API deployment/activation.

`PptxCompatibilityError` carries a code and available slide number, original object ordinal/id and source part. Upload failure/retry, workspace-copy and file-context-copy surfaces show a localized reason and ordinal in English, Traditional Chinese and Simplified Chinese. Source XML, private object names/ids and source-part paths stay out of user-facing messages; debugging retains the original cause. Account/session and projection ownership rules remain in force.

Source-preserved no-op is a separate claim: an explicitly validated source-backed graph can retain original package bytes without making retained timing/media/layout metadata editable or playable. It does not admit those features through ordinary v1 upload/copy. Source run/field/hyperlink edits still reject when original boundaries cannot be reconciled safely; the soft-break fix only expands known newline boundaries and preserves one-to-one source run properties.

## Final review fixes

- v1 rejects picture/shape reflection, shape effect lists and nonzero inherited/local paragraph before/after spacing with the current original-node location, before writes. Explicit false reflection, zero spacing and decimal numbering remain accepted. These visual properties await their later model/rendering slices.
- Effective picture bullets and non-decimal numbering fail explicitly instead of losing markers or becoming decimal. Local no-bullet overrides remain authoritative.
- Retained-source edits that change physical soft-break topology return `source-conflict` before exporting incorrectly associated language/opaque run metadata. Same-topology style/position changes and original-byte no-op remain supported.
- Notes traverse DrawingML paragraph content in order, retaining consecutive/trailing soft breaks as newlines through ordinary import/export/reopen.

The four issues have 18 reproducing regressions plus three represented-value positive controls. Final affected suites pass 144 tests; independent Office checks on freshly generated files pass 8/8 (.01pt maximum horizontal deviation), and the rebuilt browser passes all 25 affected cases in one run (33.4s). Full-suite runs exposed four incomplete XML fixture doubles, then four 5s timeouts while running Office/browser jobs concurrently. The fixture now implements the real `children()` API; Two-worker full verification passed 3771 tests before the final native numbering check; the final product passed all 3773 tests with one worker and unchanged timeouts. A later two-worker run had one unrelated PresenterGrid 5s timeout, whose 12 tests passed separately (4.22s). These load-sensitive failures are retained, not reported as CI acceptance. No product validation or assertion is relaxed.

Native export also rejects Roman/letter numbering in existing `.lpdeck` documents instead of silently changing their format to decimal. A format shown by the existing ribbon is not proof of end-to-end support; consistent non-decimal renderer/export behavior remains a later text slice. Source-backed no-op keeps the original package. Other DrawingML combinations have not been exhaustively reproduced; this matrix is the documented coverage, not a conformance guarantee.
