# Editable PPTX compatibility matrix

## Admission and preservation policy

Ordinary upload and raw/provider “Edit a copy” use the same bounded package inspection, source-feature checks and conversion validation. Unsupported input fails before creating an editable catalog item, document blob or read-only-source draft. The original record and bytes remain intact. Supported ordinary imports/copies write schema v1; read-only sources create the existing local draft. Source-backed v2 fixtures remain explicit test paths pending separate API deployment/activation.

`PptxCompatibilityError` carries a code and available slide number, original object ordinal/id and source part. Upload failure/retry, workspace-copy and file-context-copy surfaces show a localized reason and ordinal in English, Traditional Chinese and Simplified Chinese. Source XML, private object names/ids and source-part paths stay out of user-facing messages; debugging retains the original cause. Account/session and projection ownership rules remain in force.

Source-preserved no-op is a separate claim: an explicitly validated source-backed graph can retain original package bytes without making retained timing/media/layout metadata editable or playable. It does not admit those features through ordinary v1 upload/copy. Source run/field/hyperlink edits still reject when original boundaries cannot be reconciled safely; the soft-break fix only expands known newline boundaries and preserves one-to-one source run properties.

## Independent soft-break acceptance

On 2026-10-12, actual exporter outputs were read by isolated LibreOfficeDev 26.8.0.0.alpha0, rendered to PDF and independently re-saved as PPTX. Eight output cases cover same/mixed run styles, native export, source no-op, source position edits and source font edits. All preserve one paragraph, one soft break and one bullet. PDF text, actual font families, glyph sizes and line geometry pass: maximum unchanged/expected-moved horizontal deviation is 0.01 point; a two-canvas-unit source font edit renders the expected 1.5-point increase. HHC source exports retain break language and opaque metadata. Office re-save retains the paragraph, break and exact two text runs.

The original failing evidence is retained: literal LF export changed bullet placement, dropped break metadata and rejected same-style source font edits. A separate implicit-list probe revealed unresolved native indentation; those v1 inputs now fail explicitly, while source-backed no-op retains their original bytes. Supported acceptance fixtures use explicit source margins, with no guessed Office defaults.

The test uses a task-owned Office profile and process-only fontconfig. It is not Microsoft PowerPoint, exact installed-font, physical Windows/projector or large-deck acceptance. Whole-slice browser/Electron acceptance and fresh review are recorded after the final verification task. No CI, merge, API activation, deployment or release is implied.

Task 3 repository verification: 309 Vitest suites / 3750 tests passed, both typechecks passed and lint passed without warnings. Final slice gates and review follow in Task 4.
